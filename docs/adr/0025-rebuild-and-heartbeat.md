# 0025. Fast rebuild from a config bundle and an external heartbeat

Status: accepted, 2026-11-08. Design: [DESIGN.md](../DESIGN.md).

## Context

Without high availability (ADR 0024), the loss of the gateway host must be detected from outside and repaired quickly. On-host alerts cannot report the host's own death.

## Decision

- `scupper config bundle` exports all config versions, meta, head and the persisted selection, with a sha256 manifest and no secrets; the Mac agent keeps copies. `scupper install --bundle FILE` restores it on a fresh host, extracting into staging with an exact member allow-list, regular files only and size limits, and validating everything before it moves into place. Provider keys and the `wg0` key are regenerated by default (or restored by the operator out of band). A documented runbook targets about 10 minutes; the M2 migration is its first exercise and M6 adds a timed rehearsal.
- scupperd sends an external heartbeat every 60 s via the uplink to a configured dead-man-switch URL, only after a complete iteration with a fresh full check: either only when the verdict is 0, or with the exit code appended. Only healthchecks-compatible services are supported, since the service must alert when pings stop. Each delivery child carries a deadline and never sends after it.

## Alternatives considered

- No heartbeat: a dead gateway is noticed only by the Mac losing its tunnel.
- Bundles including keys: violates I6.

## Consequences

- "Gateway dead" and "scupperd dead" become visible off-host; the heartbeat is truthful because it is derived from a verdict. It covers the gateway side; whether a client reaches the gateway is shown by client handshakes and the Mac's own checks.
- A rebuilt gateway with a new `wg0` identity needs the Mac re-enrolled.
