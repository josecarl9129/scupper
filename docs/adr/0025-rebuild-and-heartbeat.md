# 0025. Fast rebuild from a config bundle and an external heartbeat

Status: accepted, 2026-11-08. Design: [DESIGN.md](../DESIGN.md).

## Context

Without high availability (ADR 0024), the loss of the gateway host must be detected from outside and repaired quickly. On-host alerts cannot report the host's own death.

## Decision

- `scupper config bundle` exports all config versions, meta, head and the persisted selection, with a sha256 manifest and no secrets; the Mac agent keeps copies. `scupper install --bundle FILE` restores it on a fresh host, extracting into staging with an exact member allow-list, regular files only and size limits, and validating everything before it moves into place. Provider keys and the `wg0` key are regenerated by default (or restored by the operator out of band). A documented runbook targets about 10 minutes; the M2 migration is its first exercise and M6 adds a timed rehearsal.
- scupperd sends an external heartbeat every 60 s via the uplink to a configured dead-man-switch URL, only after a complete iteration with a fresh full check: either only
  when the verdict is 0, or with the exit code appended. A fresh, verified session-only
  3 uses a neutral `/log` POST in status-code mode only when the report's typed
  `SessionReadinessLog` classification is `ClientSessionsReset` or
  `HistoryReconstructing`; healthy-only mode withholds both. Protection and exit
  verification must pass and telemetry must be valid and current; verdict ordering
  (`ClientSessionTelemetryUnknown` wins first) plus the warning allow-list enforce this.
  Reset allows only `ClientHandshakesStale`, `IdleClientSessionsReset` and
  `ClientSessionsPending`. History reconstruction after a start or an observation gap
  requires `ClientSessionsUnknown` with `ClientSessionHistoryUnavailable`, with only
  that warning plus `ClientHandshakesStale`, `IdleClientSessionsReset` and
  `ClientSessionsPending` allowed. Reconstructing history requires roughly 180 s of
  complete samples.

  The sampler does not distinguish starts from runtime stalls, missed cadence slots,
  writer contention, quarantined records, open barriers or durable-write fallback; no
  provenance state is added. The accepted trade-off is that a persistent runtime history
  fault, including durable-write failure, is paged only by monitor timeout, not
  immediately; the on-host `client-session-history-alert` event still fires. `ok_only`
  never pages immediately anyway. The timeout bounds the continuous absence of success,
  so brief recoveries to 0 can reset it repeatedly. A real serving failure visible only
  as stale handshakes remains exit 0 after reconstruction under the unchanged Protected-with-stale policy. Relative to 0.1.3, reset combined with peer-missing, expired-unconfirmed, telemetry-unavailable or history-unavailable warnings loses the exemption
  and receives ordinary failure reporting; this narrowing enforces the sole-cause rule.
  Missing peers, expired-unconfirmed sessions, `ClientSessionTelemetryUnknown`, other
  Unknown causes and unrelated warnings retain ordinary failure reporting.

  Both neutral logs use the fixed plain-text body `code=3 reason=ClientSessionsPending`
  followed by a newline. There is no local grace: the monitor timeout since the last
  success bounds continuous unreadiness, even across restarts that never reach 0. Log
  pings consume the ordinary interval.

  Nonzero fresh verdicts and recovery enter the bounded event log, with each (code,
  reason) key and recovery independently debounced to ten minutes and counted. A
  suppressed recovery emits once on the first healthy check after the recovery window
  expires, including suppressed transitions in its count, unless a newly logged failure
  has cleared it. Healthy flush checks do not increase that transition count. This
  tracking is per daemon process (`DaemonStarted` is the boundary); recovery after a
  restart requires a new failure observation.

  Start with at least ten minutes of monitor grace for sleep/wake resets and tune to
  measured recovery times; more grace reduces transient pages but delays real outage
  alerts. Only delivered success-class pings advance last-success status. Stored URLs
  accepted by 0.1.2 remain readable; a URL without space for `/log` falls back to `/3`
  for that ping, with action `Status` in the audit event. Log decisions record the first
  attempted request class reported by the delivery worker; preparation failure or
  timeout before an attempt records `Withheld`. Protection-verdict events do not wait
  for this report. Only healthchecks-compatible services are supported, since the
  service must alert when pings stop. Each delivery child carries a sender deadline and
  refuses new sends after it: best-effort bounded staleness, not a network delivery
  guarantee. Already transmitted packets cannot be recalled; strict freshness requires
  receiver-side expiry.

## Alternatives considered

- No heartbeat: a dead gateway is noticed only by the Mac losing its tunnel.
- Bundles including keys: violates I6.

## Consequences

- "Gateway dead" and "scupperd dead" become visible off-host; the heartbeat is truthful because it is derived from a verdict. It covers the gateway side; whether a client reaches the gateway is shown by client handshakes and the Mac's own checks.
- A rebuilt gateway with a new `wg0` identity needs the Mac re-enrolled.
